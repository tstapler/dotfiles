# ADR-009: Review surface is an append-only decision log; terminal first, static HTML second

**Status**: Accepted (amended 2026-10-16, triad repair passes 1, 2 and 3) · **Plan**: Stories 1.12, 1.13, 4.5, 7.1-7.6, 9.5

## Context
Tyler is the sole operator. Face identity and "1974 or 1984?" are visual judgments; hosting a web UI is out of scope (requirements). The repo already has a terminal `review` for flagged albums and `update-album` (`cli.py:155,221`). Comparable tools are in `research/ux.md` (its external URLs were UNVERIFIED). The triad UX review found one blocker (the meaning of a face card's Accept/Reject/Skip on a cluster sheet, which fixes the export schema) and scale gaps for the ~15k Suspect/placeholder items and 212 clusters.

## Decision
- `DATA/review/decisions.jsonl` is the single source of truth: append-only, latest wins, torn tail tolerated. All other views derive from it. `update-album` is routed through it.
- One review list with a `source` column (exactly five values, all snake_case: `album`, `file`, `audit`, `year_precision`, `placeholder`) covering per-file decisions and the 137 flagged albums (recounted 2026-10-16; the stored counter says 138 and earlier drafts said 132; assumes the owner agrees, listed as an unresolved question). Cluster labeling and face membership are `ReviewDecision` kinds (`cluster_label`, `face_member`) reached through the same verbs via a kind-handler registry, not further `source` values. **Item ids are typed and stable:** `F42` file, `A7` album, `Y77` year_precision, `U310` audit, `P4021` placeholder, `C12` cluster, `C12/F3` face. The prefix selects the source and handler (a bare number is refused), the integer is an alias allocated once per stable key and never reused (`DATA/review/ids.jsonl`, append-only and rebuildable from the log; the key is the album id, the file's `ContentKey`, `ContentKey` plus remote item id for audit, and for clusters the run number plus canonical `face_id`), every log line and export entry carries both `item` and `item_key`, and the fold identifies a decision by `(kind, item_key)`, so a re-fuse can never attach a decision to another item and the aliases can be rebuilt from the log.
- **Per-source verbs** (the table is in `design/ux.md` S3): `accept|reject|skip|set` mean one thing per source and the `Next:` line prints only that source's verbs. A placeholder item has explicit aliases `review confirm-genuine` and `review confirm-placeholder` so the bare word `reject` never has to be read as "this is genuine". **Each kind also declares whether its reject is terminal or holds** (`SOURCE_VERBS[kind].reject_terminal`): terminal for `placeholder` (genuine), `audit` (false positive cleared), `cluster` and `face`; hold for `file`, `album` and `year_precision`. A `skip` and a hold-kind reject leave the item *parked* (not undecided, writes and releases nothing, served again by `--state parked`); a terminal reject completes it. A *terminal decision* is the latest non-retracted `accept`, `set` or terminal-kind `reject`. The fold, `--state`, the `All N items decided` line, `status` (and its `Next:` order), the upload gate and the import conflict rule all read that one attribute. Review screens say `parked` and `cleared`; `Held` (plan) and `Blocked` (upload) never appear on them.
- **Cluster sheet semantics (resolves the blocker).** Cards are faces. The face buttons are `Same person` (`face_member`/`accept`, confirms membership), `Not this person` (`face_member`/`reject`, a cannot-link) and `Unsure` (`skip`); none of them labels anything. Only a cluster-level `accept` labels (every member that is not face-rejected, viewed or not) and it carries the required `name`, chosen from a closed list of `people.toml` names and exported. Ids are `C12` (cluster) and `C12/F3` (face by position in the cluster for the current `cluster_run_id`); the export also carries the canonical `face_id` (`ContentKey` + bbox) and the `cluster_run_id`. **One definition of merge and split:** `review split C12 --faces F3,F9` is two `face_member reject` lines under one `batch_id` (no `split` action exists); `review merge C12 C40` is one terminal-only `cluster_link` line with `action=merge` (must-link), and sheets never export it. **Run guard:** terminal and no-JS card commands take `--run CR7` and refuse on mismatch; `review import` ignores `cluster_label` entries whose `cluster_run_id` differs and applies `face_member` entries by canonical `face_id` (an entry whose face no longer exists is ignored); labels, face rejects and intents are stored by `face_id` and survive renumbering, while cluster-level reject/skip are valid only for the run that recorded them, and a cluster's status after renumbering is derived from its members' labels (`Accepted: <name>`, `Partly labeled`, `Mixed names`, Undecided). **Fold order:** labels are the fold of the log (members of the accepted cluster minus faces whose latest decision is `reject`), so a face reject after the accept removes the label and `review reject C12` on an Accepted cluster previews the label count first.
- **Export schema `gpo-decisions/2`**: `{schema, export_id, sheet{id, kind, generation, cluster_run_id, generated_at}, items[{kind, item, face?, face_id?, action, value?, name?, decided_at}]}` plus a `group` kind (`group_id, source, scope, album, signals, outcome, count, sample_hash, exceptions`); items carry `item` (the typed id) and `item_key`, and an album `set` carries `value` or `offset`. `decided_at` is required on every item so the newer-terminal-decision conflict rule is evaluable (terminal as defined above, so a later `skip` never blocks a sheet entry); `group_id` (sha256 over source, scope, album, sorted signals) keeps different groups from colliding. Dedup key `(kind, item_key | group_id, face, action, value | offset | name | outcome + hash(exceptions))`. **A group decision is materialized**: one `group` line plus one owner record per selected, non-excepted file (never expanded at read time), exceptions are united across lines with the same `group_id` and `outcome` (a re-export never replaces them; an exception is lifted only by deciding that file or undoing the line), stale exceptions are dropped, files added later stay Undecided, overlapping groups resolve per file by the latest record, and a placeholder sample sheet is a single page of at most 200 cards so a group's controls and exceptions are never split across pages. `ReviewDecision.kind` values, one snake_case spelling everywhere: `file`, `album_date`, `cluster_label`, `face_member`, `cluster_link`, `year_precision`, `audit`, `placeholder`, `group`, `remediation`; actions: `accept`, `reject`, `set`, `skip`, `done`, `waive`, `merge`, `retract` (there is no `split` action). The export filename carries sheet id, run and timestamp, and `review import --latest|--glob` finds it.
- **Review at scale**: filters on `review next|list` (`--source --album --severity --order --state undecided|skipped|rejected|parked`), progress counted per source, unfiltered `review next` never serving per-file placeholder items, `--by album`, `--open`; group decisions at album or signal scope with a dry-run preview, an `--except IDS` list (excepted files stay Suspect and Undecided), a sample-sheet-generated precondition above 50 files (worded as such: the tool cannot know it was looked at; an Export-originated group entry also satisfies it), a sample that scales with group size and is stratified by exact EXIF timestamp with a timestamp histogram, and one-step retraction; placeholder sample sheets; paginated date-group sheets (100 cards per page, placeholder sample sheets excepted) with a cluster index and prev/next links; name validation against `people.toml` with did-you-mean. `review undo-last` retracts the last non-retracted decision or batch (no "session"), printing what it will undo.
- Terminal commands first (`review list|next|accept|reject|set|skip|undo-last|merge|split|sheet|import|confirm-genuine|confirm-placeholder`; the legacy `review` command is migrated to `review list --source album` with an alias that warns on stderr, plan Story 1.11); every error message states what happened and the exact next command.
- Static offline HTML contact sheets (`report_html.py`) are a second layer: keyboard accept/reject (`a`/`r`/`s`/`u`/`e`/`?`, active only while a card has focus, with an off switch), every function reachable by Tab, Shift+Tab and Enter/Space with shortcuts off (every card control is in the natural Tab order, at most 5 stops per card, 6 on date-group sheets, the last being `Next undecided card`, which jumps to the next undecided card; there is no roving tabindex, arrows are an enhancement and no composite role is claimed), `aria-pressed` toggle buttons in a `role="group"` (a radiogroup was rejected: one tab stop plus arrows, and it cannot be cleared), `aria-disabled` Export, an `<li>` containing the group (no role on the `<li>`), a typed-name `<dialog>` only when fewer than 25% of the labeled members were shown, a visible counter separate from a throttled live region, meaningful alt text per sheet kind, validated `Set date` fields, 4.5:1 contrast (focus ring and state icons included, both themes), 200% zoom and text-spacing checks, native buttons, `prefers-color-scheme`, no external assets, written under `DATA/`. Decisions persist in `localStorage` keyed by sheet id plus a content/generation hash; in-sheet undo and clear; `In log:` badges for already-decided items. Export `decisions-<sheet>-<run>-<generation>-<time>.json` merged by `review import` (dry-run default; it regenerates the index).
- **Confirmation tiers, reversal map and vocabulary are one shared rule** (`design/ux.md` S12, implemented once in Story 1.13): T0 dry-run, T1 immediate (one item or small write, one-command undo), T1a preview then `--apply`, T1+ explicit override flags (the refusal or dry-run that precedes them is the preview), T2 typed token for writes and uploads, T3 typed token plus precondition for purges and gate overrides. **The typed token is a count taken from the summary (files to write, albums to upload, snapshot files to destroy, files to overwrite, the album's file count) that is not on the command line and is not printed in the prompt; `1,214` and `1214` both match, and a collision with argv falls back to the next candidate count or refuses cleanly, never raises**; a plan, run or album id given as an argument is never the token, which is why `deny release ALBUM` and `upload --i-verified-trash ALBUM` ask for the album's file count. One reversal map (`status --explain reverse`) covers `review undo-last`, `undo --run`, `placeholders revert`, `prewrite restore`, `recover`. Review-state words (`Accepted/Rejected/Skipped/Undecided`, with the per-kind meaning in parentheses), review leftovers (`parked`, `cleared`), fusion outcome (`Needs review` for enum `Review`), plan buckets (`Held`), upload (`Blocked`, `uploaded_unverified`), import housekeeping (`Ignored`, `Not imported`), write state (`Read-back OK` for enum `Verified`), backup (`attested`) and audit (`Audit-clear`) never share a word; a scan test with an explicit allow-list enforces rules V1 to V5.
- A `UserOverride` becomes a hard anchor and improves calibration.
- **Usability pass first** (Story 7.5): a timed operator run on a fixture corpus before Stories 7.2 and 7.3 are built; its outcome is recorded in the "Usability pass outcome" section below and may change their acceptance criteria. It runs on synthetic faces (real clusters do not exist until Story 4.4), so it measures the mechanics, not the time to judge aging faces; thresholds (25 s per cluster label, 15 s per file item, 2 switches and 3 import runs per 10 labels, 120 s per placeholder album) are judged on projected totals (212 labels x 25 s, 172 items x 15 s, 31 placeholder albums x 120 s) and the same quantities, plus how often the typed-name dialog fires, are re-measured on the first 20 real clusters in Story 7.3.

## Consequences
History and reversibility for human input; resumable review; one schema for sheet and terminal. No server. HTML cannot write files directly, so Export plus `review import` remains a two-step seam, softened by `--open`, the index and `In log:` badges. The typed-token rule protects against a reflex Enter, not against a deliberate copy from the summary line; this is stated rather than hidden.

## Alternatives rejected
Mutating `album_mapping.json` for decisions (no history); a local web server (out of scope); terminal-only (poor for faces); inline terminal images (terminal support UNVERIFIED); renaming `fix-metadata` to a verb that pairs with `plan` (touches every `Next:` line and the legacy muscle memory for no capability; the pairing is taught by help panels and the `plan` output instead); typing the plan id (or the album id) as the confirmation token (it is already on the command line); a `split` log action (it duplicates two face rejects); a free-text `<datalist>` name field (typos surface only at import); treating the Export of a sample sheet as proof that it was looked at (the wording says only that it was generated).

## Usability pass outcome
Empty until Story 7.5 runs: seconds per cluster label, per file item and per placeholder album, terminal/browser switches and import runs per 10 labels, thresholds (25 s, 15 s, 120 s, 2, 3), the projected totals for 212 clusters, 172 items and 31 placeholder albums, the synthetic-faces limitation, and any acceptance-criteria changes made because of it. Re-measurement on 20 real clusters (Story 7.3 owner pass) is appended here.
